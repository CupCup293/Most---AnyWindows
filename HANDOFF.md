# Промпт для нового чата Codex

Продолжи проект «Мост» в корне репозитория. Начни с `README.md`, `COMPATIBILITY.md`, `verified/rufus-media-regressions.txt` и текущего состояния Git. Цель №1 — довести Rufus 4.15 x86-64 до 90% проверенного функционала. Долгосрочная цель — 10% Windows-программ с 90% функционала, измеренных на обоснованной выборке. За проход проверяй до 2–3 программ, пока приоритет у Rufus. Указывай результаты сквозных сценариев отдельно от запуска окна и покрытия импортов.

«Мост» — Linux GUI и CLI на C++20/Qt 6. Анализирует PE32/PE32+ и импорты без запуска, автоматически распаковывает UPX во временной изоляции, по умолчанию собирает соседний ELF. Общий сценарий переводит ограниченный набор инструкций x86 PE32, выбранные Win64-профили статически перелинковывают код и ресурсы с локальным слоем Win32. Для готового ELF сохраняй условие запуска без Wine, Proton, Steam и исходного EXE. Исходный Windows-файл должен оставаться неизменным. При этом его можно использовать для сборки. Основные точки входа — `src/engine.cpp`, `src/win64.cpp`, `runtime64/host.inc`, `runtime64/launcher.c`, `runtime64/gui.cpp`.

Для Rufus используй `~/Downloads/rufus-4.15.exe`, если он доступен. SHA-256 упакованного оригинала — `84c8a437f8af89257524478489e5c85f1edf25f761d299e2bcde46ac0afbe106`. В локальном проекте последняя проверенная сборка лежит в `preview/rufus-linux`. Бинарник Rufus и оригинальный EXE не входят в исходный Git-коммит.

```sh
sh tools/fetch-deps.sh # один раз после клонирования, нужны curl и bsdtar
make
mkdir -p /tmp/most-rufus
./most analyze "$HOME/Downloads/rufus-4.15.exe"
./most build "$HOME/Downloads/rufus-4.15.exe" -o /tmp/most-rufus/rufus-linux
file /tmp/most-rufus/rufus-linux
sh tests/rufus_media_smoke.sh /tmp/most-rufus/rufus-linux
sh tests/rufus_media_smoke.sh /tmp/most-rufus/rufus-linux --mbr-target
sh tests/rufus_media_smoke.sh /tmp/most-rufus/rufus-linux --gpt-target
sh tests/rufus_media_smoke.sh /tmp/most-rufus/rufus-linux --corrupt-gpt-target
sh tests/rufus_media_smoke.sh /tmp/most-rufus/rufus-linux --write-gpt-target
```

Сборка сохраняет существующий ELF, поэтому для каждого прогона используй свободный путь. Нужны Qt 6 Widgets/Concurrent с заголовками, make, GCC/G++, pkg-config, bubblewrap и prlimit. Медиа-тест использует dosfstools, sfdisk, binutils и /dev/kvm.

**Проверено.** Интерфейс Rufus открывается. Прямая запись несжатого загрузочного образа проходит на пустом файловом носителе и на образах с MBR/GPT. Результат совпадает побайтово и загружается в KVM. При замене GPT образом без GPT стирается старая резервная GPT и сохраняется соседний сектор. GPT с неверной CRC отклоняется. `--list-usb` находил Kingston, но у текущего пользователя не было прав чтения/записи. Для запуска вне песочницы есть `--native`, для явного выбора USB — `--native --usb /dev/disk/by-id/usb-ИМЯ`.

**Следующий шаг.** Проверка сжатого загрузочного образа была остановлена до запуска. Расширь `tests/rufus_media_smoke.sh` или используй его как основу. Сожми тестовый FAT-образ в формат, который поддерживает оригинальный Rufus 4.15. Передай сжатый файл через `RUFUS_PROBE_PICK`, проведи операцию через GUI, сравни выход с исходным несжатым образом и запусти загрузочный сектор в KVM. При сбое собери полный журнал Rufus и устрани первый подтверждённый блокер в слое совместимости. Затем продолжи с форматированием и созданием установочного носителя в ISO-режиме на временных файловых образах. Физическую запись проверяй только на отдельно разрешённом к стиранию устройстве. Не считай обнаружение Kingston доказательством записи.

Порог 90% открыт. Ещё предстоит проверить физический USB, ISO-режим Linux и Windows, форматирование и создание разметки, Windows To Go, FreeDOS и другие операции из `COMPATIBILITY.md`. Продолжай по результатам тестов и фиксируй ограничения отдельно.
