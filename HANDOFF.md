# Промпт для следующего прохода по проекту «Мост»

Продолжи работу в `/home/imc/Projects/most-native` или в корне рабочего клона
`CupCup293/Most---AnyWindows`. Начни с `git status --short -b`,
`git log -5 --oneline`, `README.md`, `COMPATIBILITY.md` и
Проверь в журнале наличие изменений виртуальной флешки и доступа к USB через UDisks2.
Сохраняй незакоммиченные изменения пользователя.

## Цели и правила измерения

1. Приоритет — Rufus 4.15 x86‑64 и 90% его основных пользовательских операций.
   За проход проверяй до 2–3 программ. Пока Rufus остаётся приоритетом,
   выбирай только его, если другая программа не помогает воспроизвести общий блокер.
2. До реализации зафиксируй версию матрицы сценариев, критерии приёмки и
   знаменатель. Отдельно покажи результат по прежним десяти группам из
   `COMPATIBILITY.md`. Полностью засчитывай группу после всех заранее
   перечисленных обязательных проверок. Частичный успех записывай отдельно.
   Разделяй окно, привязку импортов, обнаружение устройств и сквозные операции.
   Для ISO-носителя требуй содержимое и загрузку, для форматирования —
   корректную разметку и файловую систему, для записи образа — сверку и загрузку.
3. Исходный PE можно читать при сборке. Проверяй неизменность SHA‑256.
   ELF должен работать без исходного EXE, Wine, Proton и Steam.
   Используй новый путь для каждой сборки. Не добавляй EXE и собранные
   ELF в Git.

## Исходная точка

- Для входа используй `~/Downloads/rufus-4.15.exe`, если он доступен.
  SHA‑256 упакованного оригинала
  `84c8a437f8af89257524478489e5c85f1edf25f761d299e2bcde46ac0afbe106`.
- Пройдены запись несжатого образа на файловые носители и запись gzip.
  Проверены совпадение байтов и загрузочный маркер в KVM, чтение MBR/GPT,
  отказ для GPT с неверной CRC и очистка старой резервной GPT.
- GUI собирает новый ELF рядом с EXE, сохраняет прежний ELF и предлагает
  виртуальный носитель либо физический USB. Kingston на 57,7 ГБ открыт
  через UDisks2. Rufus увидел устройство и прочитал GPT и FAT32
  `GPARTEDLIVE`. Это результат чтения.
- В режиме `--format` Rufus создаёт один первичный раздел FAT32 LBA в MBR,
  затем ждёт логический том до тайм-аута. Alpine Virt 3.22.0 распознаётся
  в GUI, но Start останавливается на `SetWindowsHookExW(WH_MOUSE)` перед
  выбором ISO/DD. Приоритетны эти два блокера.
- Основные точки входа — `src/engine.cpp`, `src/win64.cpp`,
  `src/gui.cpp`, `runtime64/host.inc`, `runtime64/launcher.c`,
  `runtime64/gui.cpp`, `runtime64/filedialog.inc`.

## Порядок работ

1. **Воспроизведи исходное состояние.** При необходимости запусти
   `sh tools/fetch-deps.sh`. Собери `make` и `make gui-smoke`.
   Создай временный каталог через `mktemp -d`. Собери Rufus через
   `./most build "$HOME/Downloads/rufus-4.15.exe" -o "$scratch/rufus-linux"`
   и проверь `file`. Прогони `sh tests/rufus_media_smoke.sh` с новым ELF
   в режимах по умолчанию, `--mbr-target`, `--gpt-target`,
   `--corrupt-gpt-target`, `--write-gpt-target` и `--gzip`.
   Отдельно сохрани полный журнал ожидаемого отказа `--format`.
2. **Доведи MBR/FAT32 до результата на файловом носителе.** После
   обновления разметки представь первичный раздел как логический том
   с собственным смещением и длиной. Отклоняй запросы за границами раздела
   и сбрасывай состояние тома при изменении разметки. Проверь, какой API
   Rufus вызывает следующим, и реализуй минимальный контракт на основе
   полного журнала. Критерии приёмки — `sfdisk --verify`, корректные
   границы раздела, `fsck.fat -n`, метка и контрольные байты вне раздела.
   Повтори для GPT/FAT32 отдельным тестом после подтверждения MBR/FAT32.
3. **Доведи Linux ISO до записи и загрузки.** Зафиксируй официальный
   образ Alpine Virt 3.22.0 x86‑64 и его SHA‑256
   `c935c3715c80ca416e2ce912c552f0cbfd8531219b7973ae4a600873c793eb1b`.
   Разбери роль `WH_MOUSE` в исходниках Rufus 4.15 и обеспечь работу
   диалога на потоке Qt. В тесте явно выбери ISO-режим, проверь журнал,
   структуру файловой системы и совпадение выбранных файлов из ISO.
   Проверь загрузку до ожидаемого состояния установочного окружения
   в виртуальной машине. Для отсутствующих компонентов загрузчика
   зафиксируй версию, источник и контрольную сумму.
4. **Расширяй матрицу после этих проверок.** Следом проверь Windows ISO
   на временном образе с загрузкой до экрана установки. Отдельно веди
   FreeDOS, MS-DOS и Windows To Go, поскольку у них разные зависимости.
   Зафиксируй проверки сохранения образа, сбойных блоков и отмены.
   Для физического USB начни с точного имени и размера в GUI. Проверяй
   отказ при отмене авторизации, занятом устройстве и выборе раздела.
   Запись разрешена только на явно указанном пользователем накопителе,
   который разрешено стереть. После записи проверь данные и загрузку.
5. **Проверь обычный пользовательский путь.** На реальном сеансе Wayland
   собери Rufus через «Мост», открой через меню, выбери образ с кириллицей
   или пробелами в пути и доведи виртуальную запись до результата.
   Проверь отказ в авторизации USB и видимое сообщение об ошибке запуска.
   Не меняй ACL и не запускай гостевой код от root. Сохраняй делегирование
   доступа только к выбранному устройству через UDisks2/polkit.

После каждого этапа обновляй `COMPATIBILITY.md` и журнал регрессий.
Фиксируй точную команду, вход, ожидаемый результат, наблюдение и первый
подтверждённый блокер. Повторно запускай затронутые тесты. В итоговом отчёте
приводи долю подтверждённых групп, частичные результаты, состояние
окна и импорты в разных строках.

## Долгосрочная цель

После Rufus отдельно измерь долю Windows-программ, достигающих 90%
сценариев. Сначала определи границы генеральной совокупности, например
настольные Windows-приложения из зафиксированных каталогов на заданную
дату. Сформируй воспроизводимую стратифицированную выборку по категориям,
архитектуре и типу приложения, зафиксируй источники, правила исключения
и seed. Определи сценарии до переноса. Веди общий знаменатель, показывай
непроверенные отдельно, публикуй долю и интервал неопределённости.
Заявляй достижение 10% только по результату этой выборки с явно
указанным правилом принятия решения. Используй результаты для выбора
общих доработок Win32 и следующих программ.
