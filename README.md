# Мост · PE → ELF

Настольное приложение, CLI, анализатор PE, генератор кода и слой совместимости
переписаны на C++. Окно использует Qt 6. Декодер x86 — нативная библиотека
Capstone 5.0.7 из каталога `lib`.
## Открытие без терминала

Готовый бинарник собран под Linux x86-64 с системным Qt 6.12. На другом компьютере
потребуются совместимые Qt 6 Widgets и Qt 6 Concurrent, glibc и libstdc++.
Для создания ELF нужен `g++` в системном PATH. Анализ и окно работают без компилятора.

Перетащите локальный EXE в окно или выберите его в диалоге. После успешного анализа
сборка начинается автоматически. Например, рядом с `/папка/программа.exe` появится
`/папка/программа-linux`. Исходный EXE и существующий ELF сохраняются. Если папка
недоступна для записи или не поддерживает жёсткие ссылки, приложение покажет
ошибку сохранения. Статус «Собрано» отделён от статуса «Запуск не проверен».
ELF автоматически не запускается. Если для Rufus уже существует соседний ELF,
GUI собирает новую версию с суффиксом `-2`, `-3` и так далее.

Можно перетащить целую папку или нажать **Выбрать папку…**. «Мост» рекурсивно
проверит файлы с расширением `.exe` и соберёт совместимые рядом с оригиналами.
Итоговые счётчики видны в окне, а журнал показывает результат по каждому EXE.
Существующие ELF сохраняются, новые получают суффиксы `-2`, `-3` и далее.
Символьные ссылки внутри папки пропускаются. Сопутствующие данные остаются на
месте, а Windows DLL из папки автоматически не переводятся.

Стандартные UPX-файлы распаковываются во временную папку встроенным UPX 5.2.1
с ограничением времени. Для изоляции распаковщика нужен `bwrap`. Исходный EXE
доступен распаковщику только для чтения.
Успешная распаковка не меняет требования к формату и вызовам Windows.

## CLI и сборка приложения

```sh
./most analyze /path/to/app.exe
./most build /path/to/app.exe
./most build /path/to/app.exe -o /path/to/existing-folder/app-linux
```

Коды CLI — 0 при успехе, 2 при отказе анализа и 1 при ошибке сборки. Для пересборки
самого «Моста» нужны C++20, make, pkg-config и заголовки Qt 6.

```sh
sh tools/fetch-deps.sh # один раз после клонирования, нужны curl и bsdtar
make
```

## Что поддерживается

- Анализ PE32 и PE32+, обычных и отложенных импортов. Общая сборка поддерживает x86 PE32 с подсистемой
  CUI или GUI и до 20 000 достижимых инструкций. Фиксированного лимита размера
  EXE или ELF нет. Размер отображаемого образа PE32 ограничен гостевым адресным
  пространством, а сборка требует достаточно памяти и места на диске.
- Анализ каталога `RESOURCE` проверяет дерево и границы данных ресурсов.
  Анализ `SECURITY` проверяет расположение и длины записей сертификатов.
  Журнал показывает количество записей. Проверка Authenticode и вызовы
  Win32 для ресурсов в общем режиме PE32 пока недоступны.
- Достижимые инструкции переводятся в C++ с прямыми переходами, затем
  компилируются в машинный код Linux x86-64. Данные невыполняемых секций
  встраиваются в ELF. Для запуска нужны системный загрузчик и совместимая glibc.
- В PE32 доступны базовые виджеты `STATIC`, `BUTTON` и однострочный
  `EDIT`, регистрация классов окон, гостевые обработчики, таймеры,
  стандартные и расширенные ресурсы диалогов, простое рисование, меню
  и текстовый буфер обмена. При использовании этих вызовов ELF связывается
  с системной Qt 6 Widgets. Поддерживаются отдельные флаги и сообщения.
  Транслятор находит адреса гостевых обработчиков в непосредственных
  операндах `mov` и `push`, а также в ограниченных таблицах указателей.
  Для EXE с данными за пределами секций слой файлов может предоставить
  гостю встроенную копию его PE при открытии собственного пути.
  Проверка оконного обработчика и очереди сообщений доступна через
  `sh tests/pe32_user32_smoke.sh`.
- Поддерживаются 32-битные `mov`, `lea`, `push`, `pop` в регистр, `cmp`,
  `test`, `xor`, `add`, `sub`, `nop`, прямые `jmp`, `je`, `jne`
  и вызовы через абсолютный слот IAT. Моделируется флаг ZF. Ошибки
  вычисляемой адресации могут обнаружиться при запуске.
- Общий режим PE32 поддерживает вызовы `KERNEL32.dll` для стандартного
  вывода, кода ошибки и завершения процесса, а также `GetCurrentProcess`,
  `Sleep`, `GetTickCount`, `CompareFileTime`, `MulDiv` и `lstrlenA/W`.
  Из `USER32.dll` доступны `CharNextW` и `CharPrevW` для перемещения
  указателя по строке UTF‑16. `SetCurrentDirectoryW`, `GetFileAttributesW`
  и `GetFullPathNameW` работают с локальными путями через виртуальный диск
  `Z:`, который соответствует корню Linux. Поддержка атрибутов ограничена
  обычными файлами и каталогами. `CreateFileW`, `ReadFile`, `WriteFile`,
  `SetFilePointer`, `GetFileSize` и `CloseHandle` поддерживают синхронную
  работу с обычными файлами с правами текущего пользователя. В этом режиме
  также доступны `MoveFileW`, `MoveFileExW`, `DeleteFileW`, `CreateDirectoryW`
  и `RemoveDirectoryW`. Перемещение поддерживается в пределах одной файловой
  системы. `MoveFileExW` принимает нулевые флаги и `MOVEFILE_REPLACE_EXISTING`.
  `SetFileAttributesW` сопоставляет `READONLY` и `NORMAL` с битами записи
  Linux у обычных файлов. `CopyFileW` копирует данные, отметки времени и
  признак «только чтение». Результат публикуется переименованием временного
  файла. Замена поддерживается для обычного файла без других жёстких ссылок.
- PE32 также поддерживает `GetModuleFileNameW` для основного ELF, `GetTempPathW`,
  `GetDiskFreeSpaceW` для локальных путей, `GetVersion` с представлением Windows
  6.2, `SetErrorMode` и `SetEnvironmentVariableW`. Переменные окружения гостя
  хранятся отдельно. Доступны `lstrcpyA/W`, `lstrcatW` и `lstrcpynW`.
- Внутренние вызовы, `ret`, косвенные переходы, Windows CRT, Win32 GUI, DirectX,
  динамические DLL, TLS, обработка исключений, асинхронный I/O и драйверы
  выходят за рамки этого прототипа.

### Экспериментальная перелинковка Rufus

«Мост» распознаёт конкретный выпуск Rufus 4.15 x86-64 по SHA-256
распакованного образа. Для него после анализа автоматически создаётся
`rufus-4.15-linux` рядом с EXE. Для сборки этого профиля нужны GCC,
pkg-config и заголовки Qt 6 и libsystemd. Для запуска в песочнице нужны Wayland, Qt 6 с Wayland-плагином
и bubblewrap. Исполняемый ELF сам запускается в песочнице. Слой Win64
и ресурсы встроены в ELF. Rufus показывает предупреждение о неофициальной сборке.

Проверены окно, выбор образа, запись в изолированный файловый носитель,
завершение операции и выполнение загрузочного сектора результата в KVM.
Для физического USB предусмотрен явный выбор устройства вне песочницы.
Обнаружение проверено, сквозная запись пока проверена на файловых носителях.
Остальные PE32+ анализируются обычным способом.

После сборки в «Мосте» выберите **Открыть Rufus → Виртуальная флешка (.img)…**. Укажите
исходный образ и новое имя файла виртуальной флешки. «Мост» создаст
разреженный `.img` ёмкостью от 8 ГиБ и откроет Rufus в песочнице Wayland.
Если Rufus покажет предупреждение о неофициальной сборке, нажмите **Yes**.
В Rufus нажмите **SELECT**, подтвердите предварительно выбранный образ,
затем нажмите **START**. Запись сохраняется в созданном `.img`. Для
проверки можно использовать загрузочный `.img` или `.img.gz`. Текущие
ограничения форматирования и ISO-режима указаны в [COMPATIBILITY.md](COMPATIBILITY.md).

```sh
./most build /путь/к/rufus-4.15.exe
./tests/rufus_media_smoke.sh /путь/к/rufus-4.15-linux
./tests/rufus_media_smoke.sh /путь/к/rufus-4.15-linux --gzip
./tests/rufus_media_smoke.sh /путь/к/rufus-4.15-linux --mbr-target
./tests/rufus_media_smoke.sh /путь/к/rufus-4.15-linux --gpt-target
./tests/rufus_media_smoke.sh /путь/к/rufus-4.15-linux --corrupt-gpt-target
./tests/rufus_media_smoke.sh /путь/к/rufus-4.15-linux --write-gpt-target
```

Для теста нужны `mkfs.fat`, GNU Binutils, GCC и доступный `/dev/kvm`.
Сценарий `--gzip` использует `gzip`. Для проверки разметки нужен `sfdisk`.
Режим `--format` создаёт MBR и форматирует первичный раздел FAT32 на
файловом носителе. Тест проверяет разметку через `sfdisk --verify` и
`partx`, а извлечённую файловую систему и её метку через `fsck.fat -vn`
и `fatlabel`.

## Контрольный тест

Контрольный PE32 вызывает `GetStdHandle`, `WriteFile` и `ExitProcess`.
ELF из этого PE печатает `Hello from a statically recompiled PE!` и возвращает
код 7. Готовый контрольный ELF и журнал лежат в `verified`.

Для воспроизведения теста нужен GNU Binutils с i386 PE.

```sh
scratch=$(mktemp -d)
tests/make-fixture.sh "$scratch"
./most build "$scratch/hello.exe" -o "$scratch/hello-linux"
file "$scratch/hello-linux"
"$scratch/hello-linux"
printf 'Код завершения: %s\n' "$?"
make gui-smoke
tools/upx/upx --force -o "$scratch/packed.exe" "$scratch/hello.exe"
./gui-smoke "$scratch/packed.exe" /path/to/rufus-4.15.exe
```

Описание формата и зависимости.
[Microsoft PE Format](https://learn.microsoft.com/en-us/windows/win32/debug/pe-format) ·
[Capstone 5.0.7 и лицензия BSD](https://github.com/capstone-engine/capstone/blob/5.0.7/LICENSE.TXT) ·
[Qt Widgets](https://doc.qt.io/qt-6/qtwidgets-index.html)

[UPX 5.2.1](https://github.com/upx/upx/releases/tag/v5.2.1) поставляется отдельным инструментом. Тексты лицензий находятся в `tools/upx`, исходный код доступен на странице выпуска.

## Профиль W32Ver x64

Поддерживается графический `w32ver.exe` из [W32Ver x64 от LTR Data](https://ltr-data.se/opencode.html).
SHA-256 исходного PE: `c87c9e8a34fc7270552f8e11239db52bea65c780e94bd4d5449796b23dd52a1a`.
Профиль повторно использует перелинковщик Win64 и добавляет ограниченную
реализацию `FormatMessageA` и динамическую привязку `RtlGetVersion`.
Версия 10.0, сборка 19045, относится к среде совместимости.

```sh
./most build /путь/к/w32ver.exe
tests/w32ver_smoke.sh /путь/к/w32ver-linux
```

Профили Win64 проверяют хеш входного PE. Результаты и план расширения
выборки описаны в [COMPATIBILITY.md](COMPATIBILITY.md).

## Запуск Win64 без песочницы

Для ELF с профилями W32Ver и Rufus доступен явный флаг `--native`.
При обычном запуске остаётся песочница. В нативном режиме ELF работает
с правами текущего пользователя.

В «Мосте» пункт **Открыть Rufus → Физический USB…** показывает съёмные
USB-диски. При нехватке прав «Мост» предлагает запросить доступ через
UDisks2 и polkit. В зависимости от системной политики доступ предоставляется
сразу или после подтверждения. Rufus работает от текущего пользователя и
получает доступ к выбранному устройству до завершения процесса. Запись
запускается отдельно кнопкой **START** в Rufus.

Для Rufus `--list-usb` показывает съёмные USB-диски, а
`--native --usb /dev/disk/by-id/usb-ИМЯ` передаёт выбранный диск.
Для системного запроса прав используется `--native --authorize-usb` с тем же путём.
Открытие эксклюзивное, системный диск
и разделы по отдельности отбрасываются. Этот путь экспериментальный.
Физическая запись и работа с произвольной таблицей разделов пока не проверены.

## RawCopy x64

Профиль RawCopy 1.3.9.16 собирается из готового PE и запускается как
консольный ELF. Передавайте Linux-пути в качестве аргументов. Доступны
обычные файлы и перенаправление stdin/stdout.

```sh
./most build /путь/к/rawcopy.exe
tests/rawcopy_smoke.sh /путь/к/rawcopy-linux
```

## CHSIZE32 x64

Этот профиль преобразует x64-выпуск утилиты CHSIZE32 в консольный ELF.
Он использует общий с RawCopy слой обычных файлов и отдельную поддержку
запуска Microsoft CRT. Сборка и проверка:

```sh
./most build /путь/к/chsize32.exe
tests/chsize_smoke.sh /путь/к/chsize32-linux
```

## FSplit x64

Выпуск FSplit из архива `fsplit3264.zip` превращается в консольный ELF.
Профиль использует общий запуск Microsoft CRT и добавляет файловые
дескрипторы, форматирование stdout и структуру старого `_fstat`.

```sh
./most build /путь/к/fsplit32.exe
tests/fsplit_smoke.sh /путь/к/fsplit32-linux
```

## FileInfo x64

Этот профиль перелинковывает консольный FileInfo из `fileinfo64.zip`.
Используйте Linux-пути или подайте обычный файл на stdin. Утилита только
читает метаданные обычных файлов и каталогов. Даты выводятся в UTC.

```sh
./most build /путь/к/fileinfo.exe
tests/fileinfo_smoke.sh /путь/к/fileinfo-linux
```

## Reptxt x64

Профиль Reptxt из `reptxt3264.zip` поддерживает изменение обычных файлов
на месте, маски Linux, интерактивный ввод и режим без учёта регистра ASCII.
Для замены нужны непустые строки одинаковой длины в байтах.

```sh
./most build /путь/к/reptxt32.exe
tests/reptxt_smoke.sh /путь/к/reptxt32-linux
```

## GetElTorito x64

Этот профиль перелинковывает `geteltorito.exe` из x64-архива. Он извлекает
загрузочный образ по умолчанию из ISO в stdout. Доступ к физическим
CD/DVD в этом профиле не реализован. Для тестов нужны bsdtar и Bubblewrap.

```sh
./most build /путь/к/geteltorito.exe
tests/eltorito_smoke.sh /путь/к/geteltorito-linux
```

## Cut x64

Профиль перелинковывает Windows-выпуск Cut из `cut64.zip` в консольный ELF.
Поддерживаются stdin, обычные текстовые файлы, выбор байтов и полей,
маски и выбор ASCII-символов. В локали UTF-8 ключи `-b -n` сохраняют
целые многобайтные символы. Ключ `-c` работает с позициями байтов.

```sh
./most build /путь/к/cut.exe
tests/cut_smoke.sh /путь/к/cut-linux
```

## GetHost x64

Профиль перелинковывает `gethost.exe` из `gethost64.zip`. Шесть
импортов WSOCK32 привязаны к Win64-обёрткам над резолвером Linux.
Прямой и обратный поиск работают с IPv4 и настройками NSS.

```sh
./most build /путь/к/gethost.exe
tests/gethost_smoke.sh /путь/к/gethost-linux
```

## EXEList x64

Профиль перелинковывает `exelist.exe` из `exelist64.zip`. Он читает
заголовки PE32 и PE32+ из файлов, не запуская их. Проверены прямые пути,
поиск по маске, включение скрытых файлов и рекурсивный поиск (`-r` или
`-s`). Чтение версий из ресурсов пока недоступно.

```sh
./most build /путь/к/exelist.exe
tests/exelist_smoke.sh /путь/к/exelist-linux /путь/к/chsize32.exe /путь/к/hello.exe
```

Для теста используется x64-выпуск CHSIZE32 из таблицы совместимости.
Файл `hello.exe` создаёт `tests/make-fixture.sh`.
