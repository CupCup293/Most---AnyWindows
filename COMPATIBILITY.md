# Измерение совместимости

Целевой порог — 90% проверенных основных функций у каждой программы.
Список ниже отслеживает отдельные выпуски. Охват всех Windows-программ
по этой выборке оценить нельзя.

Перед переносом фиксируем выпуск, SHA-256 и основные пользовательские
сценарии. Каждый сценарий считается пройденным после сквозной проверки его
результата. Доля для программы — число пройденных сценариев, делённое на
общее число зафиксированных. Для сложных программ одного прогона
из таблицы ниже недостаточно. Исходный PE доступен только при сборке,
а итоговый ELF работает без Wine, Proton и Steam.

## SteamSetup.exe x86

Проверен локальный PE32 с SHA-256
`7d3654531c32d941b8cae81c4137fc542172bfa9635f169cb392f245a0a12bcb`.
Сборка «Моста» `20261109.190041Z` разрешает 166 из 166 статических
импортов и транслирует 7 926 инструкций. `ExitWindowsEx` распознаётся
и возвращает ошибку для перезагрузки или выхода из сеанса хоста.

```sh
make
scratch=$(mktemp -d)
./most build "$HOME/Downloads/SteamSetup.exe" -o "$scratch/steam-setup-linux"
file "$scratch/steam-setup-linux"
sh tests/pe32_user32_smoke.sh
sha256sum "$HOME/Downloads/SteamSetup.exe"
```

ELF x86-64 запущен через bwrap без сети, с отдельным временным каталогом
и Qt offscreen. Исходный EXE не монтировался. Установщик прочитал
встроенные данные PE, открыл `Steam Setup` и страницу `Choose Install
Location` с полем пути, свободным местом и кнопками. Нажатие `Cancel`
завершило программу с кодом 1. В отдельном запуске ввод
`Z:\scratch\Steam` активировал кнопку `Install`. После нажатия процесс
вернул 0, но файлы Steam в каталоге отсутствовали. Сквозная установка и
запуск клиента пока не подтверждены. После нажатия в журнале видны
вызовы динамической загрузки DLL. Какая зависимость определяет этот
исход, ещё не установлено. `MOST_PE32_TRACE=1` печатает адрес вызова
Win32 и код выхода.

Контрольные PE32 проверили создание, ожидание и код завершения
дочернего Linux ELF, запуск гостевого потока, разрешение встроенного
экспорта и косвенный вызов, GDI-шрифты, кисти и цвета, списки изображений
и `InitCommonControls` по ординалу 17, выбор каталога, копирование файла,
перевод простой DACL в права Unix, запуск ELF через Shell и запись
`.desktop` через `IShellLinkW` и `IPersistFile`. В оконном тесте также
проверены сообщения, таймер, ресурсы GUI, чтение встроенного PE,
ограниченная таблица переходов и возврат из импортного переходника.

Динамическая загрузка ограничена встроенными экспортами «Моста».
Дочерний процесс запускается из локального Linux ELF. Qt-вызовы
гостя обслуживаются главным потоком. Поддерживаются отдельные режимы
GDI, Shell и файловых разрешений. COM ограничен интерфейсами ярлыка.
Отображение Steam Setup на Wayland или X11 в этом проходе не проверялось.

## Rufus 4.15 x86-64

Для цели 90% используем матрицу из десяти групп, зафиксированную в
`52b2d51`. На 8 ноября 2026 года полностью пройдены 2 из 10 групп.
Форматирование MBR/FAT32 засчитано как отдельная операция внутри группы
разметки и форматирования. Группа остаётся частичной до проверки GPT и
остальных обязательных проверок.

- Окно Rufus 4.15.2396 открывается через Qt offscreen. Проверка запуска из
  меню «Моста» на Wayland относится к предыдущему проходу.
- Перелинковщик привязал 522 слота импорта, включая заглушки. Реализацию
  вызовов оцениваем отдельно по пройденным операциям.
- `--list-usb` обнаружил Kingston DataTraveler без прямых прав на чтение
  и запись. Эксклюзивное открытие через UDisks2 и чтение GPT/FAT32
  `GPARTEDLIVE` из Rufus подтверждены в предыдущем проходе.

| Операция | Состояние |
| --- | --- |
| Прямая запись образа | Пройдена на пустом файловом носителе и на носителях с MBR и GPT. Проверены побайтовое совпадение, загрузка BIOS в KVM и удаление старой резервной GPT с сохранением соседнего сектора. |
| Прямая запись на физический USB | Kingston обнаружен. Проверено эксклюзивное открытие через UDisks2 без прямых прав пользователя на устройство. Сквозная запись и загрузка не проверены. |
| Создание установочного USB из Linux ISO в режиме ISO | Повторно распознан Alpine Virt 3.22.0 x86-64. После Start первый блокер — `SetWindowsHookExW(WH_MOUSE)` перед диалогом выбора ISO/DD. |
| Создание установочного USB из Windows ISO в режиме ISO | Не проверено. |
| Создание носителя Windows To Go и настройки установки Windows | Не проверено. |
| Запись сжатого образа | Пройдена для gzip на пустом файловом носителе. Проверены побайтовое совпадение с несжатым образом и загрузка BIOS в KVM. |
| Подготовка носителя FreeDOS | Не проверено. |
| Создание разделов MBR/GPT и форматирование носителя | Частично. На новом файловом носителе Rufus создал MBR и отформатировал один первичный раздел FAT32 LBA. Прошли `sfdisk --verify`, `fsck.fat -vn`, проверка метки `MOST FAT32` и контрольных байтов. Чтение GPT и отказ при неверной CRC прошли. Создание GPT/FAT32 останавливается на `CoCreateGuid`. |
| Сохранение образа USB и проверка сбойных блоков | Не проверено. |
| Загрузка ISO, журнал и отмена операции | Сквозные тесты отсутствуют. |

Список сценариев основан на [описании Rufus и изменениях 4.15](https://rufus.ie/en/).
Проверки основной GPT реализованы по [спецификации UEFI](https://uefi.org/specs/UEFI/2.10_A/05_GUID_Partition_Table_Format.html).

Для файлового носителя runtime публикует один первичный раздел FAT32
из первого слота MBR до создания файловой системы. Открытый том получает
своё смещение и длину. Смена разметки сбрасывает назначенную букву и
закрывает доступ через прежние дескрипторы тома. FAT32 создаёт встроенный
форматировщик Rufus. Запись метки поддержана для свежеотформатированного
FAT32 с пустым корневым каталогом. Для запуска достаточно ELF, системных
библиотек и песочницы. В прогонах исходный EXE был недоступен внутри
песочницы, его SHA-256 после сборки совпал с исходным. Команды и наблюдения
сохранены в [журнале регрессий](verified/rufus-media-regressions.txt).

## Сценарии RawCopy x64

Проверены полное копирование файла, копирование диапазона источника, запись
с заданной позиции в приёмнике, stdin/stdout, размер буфера, дифференциальная
запись при равных размерах и разреженная запись в новый файл. Отдельная
регрессия проверяет отказ для одного и того же файла, короткого приёмника
в дифференциальном режиме и отсутствующего источника.

Не засчитаны работа с физическими дисками и томами, Windows named pipes,
повтор I/O после ошибок, продолжение после ошибок I/O, обход Windows ACL
с резервными привилегиями, управление кэшем и принудительной записью.
Группировка основана на справке RawCopy и описании выпуска.

## Сценарии CHSIZE32 x64

Проверены создание файла заданного размера, увеличение файла с сохранением
содержимого, обрезка с сохранением префикса и разреженный файл размером
более 4 ГиБ. Тесты также проверяют отказ при неверном размере, переполнении
и передаче FIFO вместо обычного файла. Тест использует Linux-файловую систему
с поддержкой разреженных файлов.

## Анализ 7-Zip Extra

У этой сборки 145 статических импортов. Для первого запуска требуется
разобрать CRT MSVC с декорированными C++-именами и обработкой исключений,
OLE Automation с импортами по ординалам, а затем проверить файловый и
потоковый API на архивных сценариях. Совпадение имён импортов с заглушками
других профилей не доказывает поддержку их контрактов в 7-Zip.

## Сценарии FSplit x64

Проверены разбиение с настройками по умолчанию, задание префикса частей
и задание их размера. Во всех режимах результаты собраны обратно и
сравнены с оригиналом. Проверены неполная последняя часть, UTF-8 в путях
и отказ при совпадении имени с существующим файлом. Профиль рассчитан
на обычные файлы размером до 2 ГиБ минус один байт и пути до 248 байт.

[Выпуск FSplit](https://ltr-data.se/opencode.html), `fsplit32.exe` из
x64-архива. SHA-256:
`7dca26eadc50d561ae029a8a2d8e005b8424c7ddfe2fc5462a731e818a97daf3`.

## Сценарии FileInfo x64

Проверены размер, атрибуты файла и каталога, временные отметки в UTC,
число жёстких ссылок, идентификатор файла и получение метаданных из stdin.
Изменение атрибутов отклоняется и в зачёт не входит. Идентификатор берётся
из inode, а поле серийного номера тома использует Linux st_dev.
Время создания доступно на файловых системах, которые его предоставляют.

[Выпуск FileInfo](https://ltr-data.se/opencode.html), `fileinfo.exe` из
x64-архива. SHA-256:
`73faf7a45939719426c3c8045e94d7803e9c28c6b1b2a9cd1d6e0bf89ff4f8ff`.

## Сценарии Reptxt x64

Проверены замена равных по длине последовательностей в бинарном файле,
поиск без учёта регистра ASCII, работа с группой файлов по маске,
обработка скрытых файлов с ключом `/A` и интерактивный ввод.
Тесты также проверяют сохранность данных, когда совпадений нет или
аргументы некорректны. Утилита меняет обычные файлы на месте.

[Выпуск Reptxt](https://ltr-data.se/opencode.html), `reptxt32.exe` из
x64-архива. SHA-256:
`e3f20eadf066a757ff5a1c3025b22429e1e7f4a914e8310e8fe0cb2418f88a82`.

## Сценарии GetElTorito x64

Проверено извлечение загрузочного образа El Torito из обычного файла ISO
с побайтовым сравнением. Тесты покрывают разные размеры загрузочного
образа из каталога, синтетическое смещение выше 4 ГиБ, пути с кириллицей,
обрезанный образ, ISO без загрузочной записи и ошибку записи результата.
Чтение с физического CD/DVD не поддерживается. Проверен один из двух
задокументированных способов извлечения.

[Выпуск GetElTorito](https://ltr-data.se/opencode.html), `geteltorito.exe` из
x64-архива. SHA-256:
`4b4c5d015bdeef7d11f85fee6a496b351abad6cb59d8f23895ef779c45401a68`.

## Сценарии Cut x64

Проверены диапазоны байтов, позиции ASCII-символов, разбиение на поля
с разделителем и подавлением строк без него, вход из нескольких файлов
и по маске, а также сохранение целых многобайтных символов с `-b -n`
в локали UTF-8. Выбор по позициям символов UTF-8 через `-c` не засчитан:
эта сборка выбирает байты. Дополнительно проверены stdin, CRLF,
ошибки аргументов и отсутствующего файла.

[Выпуск Cut](https://ltr-data.se/opencode.html), `cut.exe` из
x64-архива. SHA-256:
`89935f1b5c5542792238930154f7600876ddfb77a7fb4804b853de45e9c4dbd7`.

## Сценарии GetHost x64

Проверены прямой поиск по имени и псевдониму, обратный поиск по IPv4,
поиск имени текущей машины без аргументов и ошибка неизвестного имени.
Контрольный запуск использует изолированный файл hosts и NSS без DNS.
Запуск с обычными настройками Linux также проверен на localhost.
Профиль поддерживает IPv4 и привязывает шесть импортов Winsock 1.1 по ординалам.

[Выпуск GetHost](https://ltr-data.se/opencode.html), `gethost.exe` из
x64-архива. SHA-256:
`ed4494b868914e9a1bcd108c1332fc89fdb0245bdd7279f8a4686bfa408bfe3c`.

## Сценарии EXEList x64

Проверены чтение заголовков PE32 и PE32+, поиск по маске, включение
скрытых файлов и рекурсивный поиск. Тесты сверяют архитектуру, точку
входа и число секций, проверяют вложенные и скрытые каталоги и отказ
при обрезанном заголовке. Ресурсы версии исключены из представления
PE, которое передаётся гостевому парсеру, и в зачёт не входят.

[Выпуск EXEList](https://ltr-data.se/opencode.html), `exelist.exe` из
x64-архива. SHA-256:
`3eb739f9aa4b3dda874373241e361bcabb97e9dbfd926587e75bbb3669888ea9`.
